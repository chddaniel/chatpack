title: UI Blocks

`@chatpack/ui` provides reusable React components on top of the headless
`@chatpack/client` package. It does not own authentication, profiles, routing,
or a database.

## Install

```sh
pnpm add @chatpack/ui @chatpack/client
```

Import the stylesheet once, then provide a React-enabled client and the viewer
id. User ids are opaque to Chatpack, so applications can render their own
profiles:

```tsx
import { createChatClient } from "@chatpack/client/react";
import { ChatpackUIProvider, ChatWindow } from "@chatpack/ui";
import "@chatpack/ui/styles.css";

const client = createChatClient({ baseURL: "/", basePath: "/api/chat" });

export function Chat({ conversationId, userId }: { conversationId: string; userId: string }) {
  return (
    <ChatpackUIProvider client={client} userId={userId} renderUser={(id) => <span>{id}</span>}>
      <ChatWindow conversationId={conversationId} />
    </ChatpackUIProvider>
  );
}
```

Connected blocks use public client hooks and actions. Realtime blocks do not
implement their own reconnect or polling logic. Host-controlled blocks accept
callbacks or records instead of pretending to own application policy.

Each block is exported from `@chatpack/ui` and has a corresponding catalog entry
here. Blocks that depend on host policy accept callbacks instead of embedding
authentication or user-database assumptions.

## Connected block contract

Configure one React client at module scope and pass it to
`ChatpackUIProvider`. The provider owns only the opaque viewer id and profile
renderer. It does not create users, authenticate requests, or invent profile
fields.

```tsx
import { createChatClient } from "@chatpack/client/react";
import { ChatpackUIProvider, ChatWindow } from "@chatpack/ui";
import "@chatpack/ui/styles.css";

const client = createChatClient({ baseURL: "/", basePath: "/api/chat" });

export function Chat({ conversationId, userId }: { conversationId: string; userId: string }) {
  return (
    <ChatpackUIProvider client={client} userId={userId} renderUser={(id) => <span>{id}</span>}>
      <ChatWindow conversationId={conversationId} />
    </ChatpackUIProvider>
  );
}
```

Message blocks invoke `messages.edit`, `messages.delete`, `messages.react`,
`messages.unreact`, and `messages.forward`. `MessageActions.canEdit` controls
whether edit controls render; Chatpack core remains the authorization boundary
for every mutation. `MessageComposer` sends on Enter and preserves Shift+Enter.
Message lists reverse the client's newest-first page for display and call
`markRead` for the newest item.

The main branch does not make every management surface client-connected. Invite
acceptance and leaving a group call client actions. Participant management,
channel settings, join requests, moderation, and several directory surfaces use
host callbacks or host-provided records. This keeps authentication,
authorization, profile lookup, navigation, and policy in the application.

## Media attachment boundary on `main`

The `main` branch keeps file handling host-owned. `AttachmentComposer` and
`AttachmentDropzone` return selected `File` objects through `onFiles`. The host
uploads them, checks authorization, and passes records to the render blocks.

```ts
interface ChatAttachment {
  id: string;
  name: string;
  url?: string;
  mimeType?: string;
  size?: number;
}
```

`ImageBubble`, `FileBubble`, `MessageAttachments`, and `AttachmentGallery`
render a URL when one is present. They show `UnavailableAttachment` when it is
missing. `@chatpack/ui` does not call storage routes or manage upload state
beyond the presentational `UploadProgress` block.

## Theme and usage limits

Import `styles.css` for package variables and layout classes. For small token
overrides, wrap a subtree with `ChatpackUIThemeProvider`:

```tsx
import { ChatpackUIThemeProvider, ChatWindow } from "@chatpack/ui";

<ChatpackUIThemeProvider theme={{ accent: "#2563eb", accentContrast: "#ffffff", radius: "1rem" }}>
  <ChatWindow conversationId={conversationId} />
</ChatpackUIThemeProvider>;
```

Supported keys: `surface`, `panel`, `border`, `text`, `muted`, `accent`,
`accentContrast`, `bubbleOther`, and `radius`.

The catalog is not a Slack-style thread system. `replyToMessageId` creates a
quote reply. True threads need separate root identity, pagination, unread
state, and client surfaces. The separate threaded-replies design work keeps
that model distinct.

The page documents source on `main`. The published gallery has 76 catalog names;
the package also exports a few core blocks such as `GroupList`. Behavior is split
between client-connected blocks and host-controlled presentation surfaces. Check
the source and client version together when adding a block.
